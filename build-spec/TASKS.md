# TASKS.md — 分階段建置任務

> 依序執行。**每階段完成後停下,請使用者驗收再進下一階段。**
> 每項任務的驗收標準都是可測試的;做不到就不算完成。

---

## P0 — 專案骨架與資料層

**目標:能新增一位個案、建立一筆空白服務紀錄、資料存在本機、重開仍在。**

| # | 任務 | 驗收標準 |
|---|---|---|
| 0.1 | 建立專案骨架(PWA + TypeScript 嚴格模式) | `npm run dev` 可啟動;可安裝到 iPad 主畫面 |
| 0.2 | 實作 `SPEC.md §2` 全部資料表(SQLite schema + IndexedDB 本機層) | schema migration 可重跑;欄位與規格一字不差 |
| 0.3 | 個案 CRUD | 可新增/編輯/查詢/結案個案;**禁忌症欄位存得進也顯示得出來** |
| 0.4 | 離線儲存與同步骨架 | **飛航模式下可新增個案與紀錄**;恢復連線後同步,無資料遺失 |
| 0.5 | 版本與簽章機制 | 簽章後紀錄不可直接編輯;修改產生新版本且 `supersedes_id` 正確指向前版 |
| 0.6 | 每日自動備份至指定路徑 | 備份檔可還原出完整資料 |
| 0.7 | 資料層單元測試 | 版本機制與離線同步皆有測試覆蓋 |

⚠️ **0.5 是法遵核心(CLAUDE.md C2),不可簡化。**

---

## P1 — 自費 SOAP 紀錄

**目標:一筆回診紀錄 90 秒內完成並簽章。**

| # | 任務 | 驗收標準 |
|---|---|---|
| 1.1 | 共用字典表建檔(測驗庫、動作庫、目標庫) | 測驗庫至少含 TUG、30 秒坐站、BBS、步速、SPPB、握力;輸入數值自動比對常模 |
| 1.2 | SOAP 完整模式 | `SPEC.md §2.3` 全部欄位可輸入並儲存 |
| 1.3 | **快速模式** | 1) 開啟即帶入上次 O/P 段 2) NPRS 滑桿 3) 個人常用清單置頂 4) 人形圖點選部位 |
| 1.4 | 單句語音輸入 | 各文字欄位可用 iOS 鍵盤聽寫直接輸入(不自建語音服務) |
| 1.5 | 90 秒實測 | **以真實回診情境計時,平均 ≤ 90 秒完成並簽章** |
| 1.6 | 測驗數值趨勢圖 | 同一測驗跨次數自動畫趨勢;長照/自費資料不斷裂 |
| 1.7 | 禁忌症提示 | 每次開啟紀錄,注意事項顯示於最上方且無法略過 |

## P2 — 排程與行事曆

| # | 任務 | 驗收標準 |
|---|---|---|
| 2.1 | 日/週排程檢視 | 顯示個案、地點、軌別、時段 |

## P3 — 長照申報與核銷預檢引擎

**本階段是全系統法遵風險最高處,測試覆蓋率要求最嚴。**

| # | 任務 | 驗收標準 |
|---|---|---|
| 3.1 | 長照申報模板 | `SPEC.md §2.4` 欄位完整;與自費模板資料流完全隔離 |
| 3.2 | **預檢引擎 8 項檢查** | 每項都有單元測試;刻意製造的錯誤資料能被正確攔下 |
| 3.3 | 申報狀態機 | 六個狀態轉換正確;**僅狀態 1 可修正/刪除** |
| 3.4 | 核銷月曆與提醒 | 每月 1 日提醒;**6 個月死線倒數**;額度餘額顯示 |
| 3.5 | FA400 自動提醒 | 個案標記中途結案/移居時自動提示前置設定 |
| 3.6 | QD110 匯出 | 格式符合官方規範;**自費紀錄自動排除** |

⚠️ 3.6 的格式規範需向照管平台客服取得文件後才能完成。**未取得前先做介面與資料整理,格式層留待補上。**

## 執行前必須先問使用者的事

| # | 問題 | 影響 |
|---|---|---|
| Q1 | 系統跑在哪台機器上?(Mac mini / NAS / 其他) | 決定部署方式與遠端存取設定 |
| Q2 | 目前既有個案資料在哪?(Excel / 紙本 / 其他系統) | 決定 P5 匯入精靈的欄位規則 |
| Q3 | 是否已有 LINE 官方帳號? | 決定 P4 能否開工 |
| Q4 | 長照軌現階段是自營特約,還是報備支援他所? | **若為報備支援,P3 整個階段可延後甚至不做**(核銷由對方單位處理) |

> **Q4 特別重要:** 最新評估(`reference/方案比較_一人自費治療所_vs_自營特約雙引擎.md`)建議以「一人自費治療所 + 長照報備支援他所」起步。
> 若採此路線,**建置順序改為 P0 → P1 → P2 → P4 → P5**,P3 核銷模組延後。
> **開工前先向使用者確認這一題。**
